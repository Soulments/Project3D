# 측정 기록

수치는 "측정 조건 → 기준 → 결과 → 결론" 순서로 남긴다. **기준은 측정 전에 먼저 적는다** (수치를 본 뒤에 기준을 잡으면 판단이 흔들린다).

## 1. 적 탐지 비용 (Phase 3 Step 4)

### 질문

적이 늘어나면 "플레이어를 발견했는가" 판정이 프레임 비용의 병목이 되는가?
병목이면 QuadTree(공간 분할)를 구현하고, 아니면 측정 수치와 미채택 사유를 기록한다.

### 비교 대상

| 방식 | 설명 |
| --- | --- |
| A. 거리 비교 (현재 구현) | 적마다 플레이어까지 XZ 제곱거리를 비교 (`EnemyController`) |
| B. `Physics.OverlapSphere` | 적마다 탐지 반경으로 `OverlapSphereNonAlloc` 호출 (계획서 기준 베이스라인) |

측정 구간은 Idle/Patrol 상태의 탐지 판정만이다 (추격·공격 중 거리 검사는 제외).

### 병목 판정 기준 (측정 전 확정 — 2026-11-17)

- 목표 프레임: 60 FPS = 프레임당 16.7 ms
- **적 30마리에서 탐지 비용이 프레임당 0.5 ms 이상** (프레임 예산의 약 3%), **또는**
- **적 100마리에서 프레임당 2.0 ms 이상** (프레임 예산의 약 12%)

둘 중 하나라도 넘으면 **병목으로 판단하고 QuadTree를 구현**한다. 둘 다 넘지 않으면 **미채택**하고 사유를 기록한다.

기준 설정 이유: Editor는 빌드보다 느리므로 Editor 수치로 판단해도 보수적이다. 모바일 타깃(성능 예산 Draw Call 50 이하)을 감안해 탐지가 프레임의 한 자릿수 % 이상을 먹으면 최적화 대상으로 본다.
